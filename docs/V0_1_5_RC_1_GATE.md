## Conditions before creating the tag

1. Automated Android emulator matrix passes, or any unsupported provider restriction is explicitly scoped and accepted as a release policy change with an equivalent validated scenario; do not disguise a failure as a passing check.
2. Run the full preflight again against the finalized source revision, including browser suites and native JVM/build checks, and ensure worktree clean.
3. `yarn release 0.1.5-rc.1 --dry-run`, then the release script may create the metadata commit and annotated `v0.1.5-rc.1` tag. Recheck version metadata, package identity and artifact checksum.
4. Only publish a **signed** release with the established Android keystore. The local sandbox has no keystore/secrets. `.github/workflows/release.yml` previously produced a signed RC from GitHub secrets; pushing the tag triggers the release workflow. This sandbox does not have authenticated Git SSH pushing.

Physical two-phone multi-night reliability, real networks, and the 24-hour app-attributed battery target (at most 2%) are **RC field-validation** tasks, not pre-RC automated checks. The final release remains blocked on them.
