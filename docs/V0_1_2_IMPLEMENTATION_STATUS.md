## Changes and acceptance

- Fixed ended outgoing history at its runtime/persistence owner. Authenticated recipients are recorded per link with a 128-peer bound, and ended relationships retain peer identity. Unknown and legacy links remain link-level. Same displayed names never establish identity. The common list retains active controls and related ended history, with Show ended, direction filters and protected-state reload covered by a real P2P regression.
- Migrated the complete legacy P2P suite, screenshot fixture and Pages preflight boot/reload selectors to compact common-list navigation. All 16 original scenarios and one new history scenario pass. Reciprocal return sharing uses the full normal form, explicit reception consent, configurable precision/duration and independent links.
- Corrected Android return-form background availability to reflect the actual service. A synthetic browser mount of the real ShareSheet verifies foreground/background choices and sender-specific presentation. Signed owner/recipient binding, idempotence and lost-ack reconciliation retain unit evidence.
- Expanded the existing two-source P2P workflow: ordinary disconnect produces no notice; stopping an unsaved preview while its sender is offline removes it locally, queues a protected stop-only proof, survives viewer reload and delivers once after sender restart. Timestamp, dismissal and ended-history reload persist; the other saved follow remains intact.
- Added one narrow synthetic map fixture: transparent lower-left complete avatars, displayed-name initials, accessible labels, no navigation/attribution collision, all six overflow IDs, and canonical disclosed-area fit. The same scenario then uses two real synthetic P2P sources and a controlled 250 px map surface: overflow opens the production common list with both represented peers, excludes an unrelated waiting link, and dock open restores all three rows and All filter.
- **2026-10-09 root-cause fix (return delivery on Android):** native-created source links were signed with the background service identity, while approved returns are received by the distinct foreground identity. The browser pre-bound each return link to the original link owner, so the foreground dialer was denied (`approved=true match=false`). The foreground now signs the original link's owner proof and the native source verifies and persists it before the link is presented, using the same proof-only handoff as return links; source key and foreground owner identities remain separate. The generalized `replace-background-owner` command supports source shares (no recipient binding) and return shares (single-recipient binding) with idempotent retry, forged-proof rejection and already-handed-off rejection.
- Existing expanding menu, project links, optional first-device claim, four-letter comparison and distinct direct/relay/both diagnostics remain in the working tree. The short-link scope is the [documented design review](VERY_SHORT_LINK_DESIGN_REVIEW.md); no resolver is deployed.

## Limits and remaining gates

- Physical-device acceptance has not run: real lock screen, foreground-service notification and background-location permission flow, Doze/battery restrictions, app process death under memory pressure, external default browser launching, real network transitions and trusted human four-letter comparison remain open. Emulator coverage is strong but is not a substitute.
- Native project/release link launching, allowlist rejection and missing-browser failure passed on API 29 and API 36 (`--project-links-smoke`). Pages emitted the expected missing `ANDROID_APP_LINK_SHA256` warning, so signed/deployed App Links association remains unverified.
- Full compact-row mobile accessibility and native safe areas remain partially manual; the browser and WebView automation cover the documented workflows.
- At this report's 2026-10-11 update, GitHub Actions and committed-checkout `ci:preflight` had not run. The preflight is scheduled on the clean tree after this documentation/catalog update is committed.
- Four-letter comparison has about 19 bits of SAS strength and requires explicit trusted human-channel confirmation; browser commitment/challenge/reveal success is not physical-device acceptance or formal cryptographic proof. See [security review](DEVICE_COMPARISON_SECURITY.md).
- Stop retries require the viewer app to run and sender to become reachable within seven days; the sender's 16-event ledger bounds replay deduplication; unseen out-of-order events and evicted IDs have no total-order guarantee.
